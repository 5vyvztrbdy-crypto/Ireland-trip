# Deployment Plan

## Confirmed direction

The repository should become durable company memory and support the flow: product decisions → documentation → code → tests → commit → GitHub → automated deployment. Routine development should not depend on ZIP transfers or reconstructing context.

## Planned stages

1. Establish documentation and decision history.
2. Select application and test architecture through recorded decisions.
3. Add automated verification for working capabilities.
4. Establish review and production environments.
5. Automate deployment with visible status for Sprint Reviews.

Hosting, CI/CD provider, environments, secrets, rollback, monitoring, and release approval are **TBD**.
